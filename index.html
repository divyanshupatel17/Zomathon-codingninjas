About This Project

A data-driven solution for Problem Statement 2 of the Zomathon hackathon. The system intelligently ranks add-on candidates using gradient boosting with contextual feature engineering and real-time inference capabilities.

Core Problem Challenges

  • Difficulty in understanding meal composition and identifying complementary items
  • Limited ability to recognize incomplete meal patterns (main dish without beverage)
  • Recommendations ignore critical contextual factors such as time of day and user segment
  • Recommendation must be real-time and relative to context with 200-300ms latency
  • Cold-start problem for new users, restaurants, and items

Business Success Metrics

  • Average Order Value (AOV) lift
  • CSAO rail attach rate and order share
  • Cart-to-Order (C2O) ratio improvement
  • Add-on acceptance rate (currently 39.1% in dataset)
  • Average number of items ordered per session

Methodology

Solution Approach

A multi-stage pipeline combining feature engineering, gradient-boosted ranking, and production-ready inference architecture designed for sub-200ms latency at scale.

01

Data Preparation & Feature Engineering

Generating 40+ contextual features across user, restaurant, cart, and temporal dimensions. Includes meal-completion signals, cart diversity indices, and rolling behavioral aggregates to eliminate cold-start issues.

02

Problem Formulation as Learning-to-Rank

Framed as a binary classification task (accept/reject) using LightGBM with LambdaRank objective. This enables efficient ranking of candidate add-ons while optimizing for NDCG and business metrics simultaneously.

03

Sequential Cart Context Modeling

Each cart state is tracked as items are added. The model dynamically re-scores candidates after every cart change, enabling the biryani-to-salan-to-gulab-jamun recommendation chain that drives incremental AOV lift.

04

Cold Start Strategy

New users fall back to segment-level collaborative signals. New restaurants use cuisine-category popularity heuristics. New items inherit category-level attach rates until sufficient interaction data accumulates.

05

Real-Time Inference Architecture

Pre-computed user and restaurant embeddings cached in Redis. Online feature assembly via lightweight Python microservice. LightGBM inference for top-10 candidates completes in under 50ms, well within the 200ms SLA.

06

A/B Testing & Business Impact

Proposed experiment framework with holdout control group, measuring AOV lift, acceptance rate, and C2O ratio. Guardrail metrics protect against cart abandonment increases or order completion degradation.

System Design

Inference Pipeline

End-to-end request flow from cart state to ranked recommendations, designed to meet the 200-300ms latency constraint.

1
Cart Signal
User adds item; cart state change triggers recommendation update
2
Feature Assembly
User, restaurant, temporal features fetched from Redis cache
3
Candidate Gen
Rule-based pre-filter narrows candidate pool to 50-100 items
4
LightGBM Rank
Model scores each candidate; top-10 selected by probability
5
Response
Ranked list with scores returned in under 200ms
